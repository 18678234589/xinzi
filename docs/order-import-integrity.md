# 订单导入、联系方式与结算对账

修复日期：2026-10-11（用户时区）。

无表头旧表的客户电话列原已被 `ps_import_headerless_map()` 识别，但续费资料解析仅读取表头，导致订单已导入而联系方式仍为空。现在两处共用纯解析模块 `ProjectRenewalImportFields.php`，支持带标注的唯一手机号、国际前缀和 Excel 科学计数法。遮蔽号码、多个手机号、未标注的 QQ 账号不冒充有效客户电话。明确的客户微信和联系方式列继续支持微信号。

同单附加行的续费资料会保留并合并。无标识重传已经登记过的网站时，复用唯一对应的原网站；对应关系不唯一时要求补充标识，禁止生成另一张重复订单。历史已合并的付款订单仍按原订单补充，不靠表格行数重新拆单。SSL 等附加项跟随本付款号最近一个网站。Excel 文本格式的前导单引号不再成为订单号的一部分。

结算页增加“本期订单与登记金额”和“已上传表格对账”。原表商品行、付款编号、系统订单、售价、实收、退款、已核算报酬分别显示；待核算说明读取真实核对原因。跨月旧单仅在实际补录月份显示，月份筛选有上下界；使用 `EXISTS` 避免多人参与将订单和金额重复累加。

多个网站分别登记，SSL 等附加项合并金额。系统还存在其他表格及手工录入，所以个人本期全部订单与这一份表格的对应订单数分别列出。具体生产核对结果和备份位置记录在私有连接说明中。

历史资料处理扫描 34 份已导入表格，回填只补缺失联系方式，保留现有联系方式、客户自有资源和确认过的资金记录。两个明确重复的草稿销售经过事务演练后合并；保留参与人及有效成本资料，合并前保存完整数据库备份与逐订单备份。另一个付款号的网站归属无法唯一确定时保留待核对，禁止猜测客户归属。

运维工具 `tools/repair_import_contacts.php` 默认仅生成计划；`tools/repair_order_import_duplicates.php` 默认事务内演练后回滚。`--apply` 必须配置站点之外的私有备份目录。容器中使用 `HEZUOSHANG_PROJECT_ROOT` 指定应用根目录、`HEZUOSHANG_REPAIR_BACKUP_ROOT` 指定私有备份根目录，并将逐行备份复制到宿主机持久目录。工具和备份都不发布到网站。

回归测试：`php tests/order_import_integrity.php`，要求 PHP 的 SQLite PDO 与 mbstring 扩展。测试使用独立内存数据库，不连接生产数据库；验证电话与微信解析、同号匹配、禁止重复网站、月份边界、多人参与不重复累加、真实待核对原因。生产 PHP 7.4 已运行通过，并通过真实 HTTPS 域名下的合作人员只读页面验证。测试登录会话使用独立临时会话，验证后删除。
